## 1. MOS 보고서 — 앱 이름 표시 추가

### 현상
MOS 측정 보고서(`mos_report.py`)의 "테스트 환경" 섹션에 **단말 정보, OS 버전, 앱 버전은 표시**되지만 **어떤 앱으로 테스트했는지(앱 이름)가 누락**되어 있었음.

### 원인
- 프론트엔드(`useTcRunner.ts`)에서 `test_info` JSON을 구성할 때 `android_app_name` / `ios_app_name` 필드를 전달하지 않음
- Python `mos_report.py`의 `_env_table()`에도 앱 이름 행이 없었음

### 수정

| 파일 | 변경 내용 |
|------|----------|
| `useTcRunner.ts` | `testInfo` 구성 시 localStorage `targetAppConfig`에서 선택된 앱 ID → `SUPPORTED_APPS` 조회 → `android_app_name`, `ios_app_name` 필드 추가 |
| `mos_report.py` `_env_table()` | `('Android 앱', info.get('android_app_name'))` / `('iOS 앱', info.get('ios_app_name'))` 행 추가 (앱 버전 바로 위) |

### 결과
테스트 환경 섹션에 "Android 앱: 익시오 (LG U+)" / "iOS 앱: 익시오 (LG U+)" 등 앱 이름이 정상 표시됨.

## 2. MOS 보고서 — 10회 중 9회만 표시되는 문제 수정

### 현상
10회 반복 테스트 후 MOS 보고서의 "호별 상세" 표에 **9회 평균만 표시**되고, 헤더에도 "9회 측정"으로 표시됨.

### 원인 (2단계)

**① 프론트엔드 필터 (`useTcRunner.ts`)**
```typescript
// 수정 전: PASS만 필터 → MOS 측정 실패 건은 보고서에서 완전 제외
.filter((r) => r.status === "PASS")
```
10회 테스트 중 1회가 MOS=null이면 9건만 보고서에 전달됨. 단, 이번 케이스에서는 DB 확인 결과 10회 전부 PASS여서 이것만으로는 설명 안 됨.

**② Python `_per_call_table()` (`mos_report.py`)**
```python
# 수정 전: MOS가 None이면 행 자체를 skip
if mos is None:
    continue
```

**③ Python `total_calls` 계산**
```python
# 수정 전: MOS 값이 있는 것만 카운트
total_calls = max(len(ios_mos), len(and_mos))
```

### 수정

| 파일 | 변경 전 | 변경 후 |
|------|---------|---------|
| `useTcRunner.ts` | `.filter(r => r.status === "PASS")` | `.filter(r => r.tcId === "TC_00")` (전체 포함) |
| `mos_report.py` `_per_call_table()` | `if mos is None: continue` | MOS 없는 행도 표시 (`—` + 빨간색 상태) |
| `mos_report.py` `total_calls` | `max(len(ios_mos), len(and_mos))` | `len(runs)` (전체 시도 횟수) |

### 결과
- 10회 테스트 → 헤더 "10회 측정", 호별 상세 표 #1~#10 전부 표시
- MOS 측정 실패 건은 `—`으로 표시되고 상태 컬럼이 빨간색으로 강조

## 3. 앱 버전 표시 — 전체 앱 대응 (Samsung Phone, Apple Phone)

### 현상
앱 버전 배지가 **익시오(ixi-O)에서만** 표시되고, Samsung Phone / Apple Phone 선택 시 버전이 안 나타남.

### 원인
- Rust `device_cmd.rs`의 `fetch_ios_app_version_sync()` / `fetch_android_app_version_sync()`가 **하드코딩된 패키지명**(`IOS_PKG`, `ANDROID_PKG`)만 사용
- `get_app_versions` 커맨드가 인자 없이 하드코딩된 패키지만 조회

### 수정

| 파일 | 변경 내용 |
|------|----------|
| `device_cmd.rs` | `fetch_*_app_version_sync(pkg: &str)` 매개변수화, `get_app_versions(ios_pkg, android_pkg)` 매개변수 추가, 하드코딩 상수 제거 |
| `useAppVersions.ts` | `useAppVersions(iosPkg, androidPkg)` 매개변수 수용 |
| `AppHeader.tsx` | `useMemo`로 선택된 앱의 패키지/번들ID 파생 → `useAppVersions` 내부 호출, props에서 버전 제거 |
| `DashboardView.tsx` | `appVersions` prop 제거 → 내부에서 `useAppVersions` 훅으로 직접 조회 (AppHeader와 동일 패턴) |
| `App.tsx` | `useAppVersions` import/호출 제거, `appVersions` prop 제거 |

### 결과
앱 선택 드롭다운에서 Samsung Phone / Apple Phone / A.dot 선택 시에도 해당 앱의 버전이 정상 표시됨.

## 5. `app_scanner.py` 정규식 — 전체 앱/통신사 파일명 대응

### 현상 (4월 17일 이전 발견)
`app_scanner.py`의 `_COLLECTED_PAT` 정규식이 `_ixiO_` 패턴만 매칭 → Samsung/LGU+ 태그 파일이 `analyze_hybrid.py`에서 무시됨 → 14시 세션 MOS 1.16/1.14 이상 점수 발생.

### 수정
정규식을 `^(iOS|Android)_[A-Za-z]+_(?:[A-Za-z+]+_)?(?:(TC_\d{2})_)?(\d{8})_(\d{6})\.wav$`로 일반화하여 모든 앱 태그(ixiO, Samsung, Adot) 및 통신사 태그(LGU+) 대응.
