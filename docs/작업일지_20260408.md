## 1. 폰트 크기 일관성 개선 (`App.css`)

### 배경
UI 평가에서 폰트 크기가 9px~13px 사이에서 맥락 없이 혼재한다는 점이 지적됨.  
특히 테이블 내 보조 텍스트(`td-muted` 등)가 모니터에 따라 읽기 어려운 수준(11px + muted 색상 조합).

### 개선 원칙
세 단계 타입 계층을 정의하고 모든 클래스를 여기에 맞춤:

| 레벨 | 크기 | 용도 |
|------|------|------|
| 본문/테이블 데이터 | **12px** | 읽어야 하는 콘텐츠 |
| 배지/태그 라벨 | **11px** | uppercase + font-weight로 보완 |
| 카운터/코드 전용 | **10px** | 날짜 라벨 등 최소한으로 유지 |

### 주요 변경 내역

| 클래스 | 변경 전 | 변경 후 | 비고 |
|--------|---------|---------|------|
| `td-num`, `td-time`, `td-dur`, `td-repeat` | 11px | 12px | 테이블 보조 데이터 열 |
| `td-muted` | 12px | 13px | 사용자 지적 대상 |
| `session-summary-row td` | 11px (2곳) | 12px | 세션 요약 행 |
| `tc-desc`, `stg-tc-desc` | 11px | 12px | TC 설명 텍스트 |
| `tc-info-guide dt/dd` | 11.5px | 12px | 비표준 값 제거 |
| `os-badge` | 9px | 10px | OS 태그 |
| `env-version`, `env-hint`, `env-setup-log` | 10px | 11px | 환경 패널 |
| `11.5px` 전체 (30개+) | 11.5px | 12px | 설정/세션/보고서 패널 전반 |
| `10.5px` 배지류 | 10.5px | 11px | severity/repeat/phase 배지 |

**유지한 11px:** `device-tag`, `tc-id-tag`, `audio-badge` 등 배지 계열 — uppercase + font-weight 700 + 배경색으로 시각적 보완이 이미 되어 있기 때문.

## 2. Settings 모달 i18n 미번역 수정 (`SettingsModal.tsx`, `ko.ts`, `en.ts`)

### 배경
영문 모드 전환 시 Settings 모달 내 3개 탭에서 한국어가 그대로 노출됨:
1. **Audio Profiles 탭** — 탭 메뉴명이 `보이스피싱`, `일상 대화` 한국어로 표시
2. **Script 탭** — 설명 문구에 프로파일명이 한국어 그대로 interpolation됨
3. **Recording Mode 탭** — 채널 설명이 `L채널(Ch2) = Android, R채널(Ch3) = iOS` 하드코딩

### 원인 분석
- Audio Profiles/Script 탭: `p.name`을 직접 출력 — built-in 프로파일의 `name` 필드가 localStorage에 한국어로 저장되어 있어 언어 전환이 되지 않음
- Recording Mode 탭: 채널 설명이 JSX 안에 한국어 문자열로 하드코딩

### 수정 내용

**`SettingsModal.tsx`**  
`profileDisplayName()` 헬퍼 추가 — built-in ID(`daily`, `phishing`)는 번역 키 참조, 사용자 추가 프로파일은 저장된 name 그대로 사용:

```tsx
const profileDisplayName = (p: AudioProfile) => {
  if (p.id === "daily")    return t("profiles.daily");
  if (p.id === "phishing") return t("profiles.phishing");
  return p.name;
};
```

`p.name` 3곳 → `profileDisplayName(p)` 교체 (Audio Profiles 탭 시트탭, Script 탭 시트탭, Script 탭 설명 문구).

하드코딩 채널 설명 → `{t("settings.recordingTab.directChannelHint")}` 로 교체.

**`ko.ts` / `en.ts`**  
`settings.recordingTab.directChannelHint` 키 추가:
- ko: `"L채널(Ch2) = Android, R채널(Ch3) = iOS"` (→ 이후 수정됨, 아래 참고)
- en: `"L(Ch2) = Android, R(Ch3) = iOS"` (→ 이후 수정됨)

## 3. profileDisplayName 번역 키 경로 오류 수정 (`SettingsModal.tsx`)

### 배경
수정 직후 탭 메뉴명이 번역 텍스트 대신 `settings.profiles.phishing`, `settings.profiles.daily` 키 이름 자체로 표시되는 문제 발생.

### 원인
`t("settings.profiles.daily")` 로 참조했으나 실제 i18n 파일에서 `profiles` 섹션은 최상위 키(`profiles.daily`)이며 `settings` 하위가 아님.

### 수정
```tsx
// 수정 전
if (p.id === "daily")    return t("settings.profiles.daily");
if (p.id === "phishing") return t("settings.profiles.phishing");

// 수정 후
if (p.id === "daily")    return t("profiles.daily");
if (p.id === "phishing") return t("profiles.phishing");
```

## 7. 예약 테스트 칸반 보드 실행 타이밍 버그 수정

### 현상
"대기열 추가" 버튼을 누르자마자 [대기중] 컬럼을 거치지 않고 즉시 [테스트 중] 컬럼으로 이동하며 테스트가 실행됨.  
3분 후 시작으로 설정했음에도 예약 시간을 무시하고 즉시 실행.

### 원인 분석
`schedules` state 변경마다 실행되는 `useEffect` 내부에 즉시 대기열 자동 시작 로직이 포함되어 있음:

```typescript
// 즉시 대기열 자동 실행: 실행 중인 것 없으면 createdAt 가장 앞 항목 시작
if (!isAnyRunning && !isTcRunningRef.current) {
  const next = [...schedules]
    .filter((s) => s.status === "pending" && !s.scheduledAt)
    .sort((a, b) => a.createdAt.localeCompare(b.createdAt))[0];
  if (next) {
    const tid = setTimeout(() => {
      if (!isTcRunningRef.current) fireEntry(next);
    }, 100);  // ← 100ms 후 즉시 실행
    timerRefs.current.set(next.id + "-q", tid);
  }
}
```

`scheduledAt`이 설정된 항목은 건너뛰도록 필터(`!s.scheduledAt`)가 있으나, `handleAdd()` 내에서 `formAt` 입력값이 entry에 올바르게 전달되지 않는 경우 또는 해당 필터 외에 별도 경로로 `fireEntry`가 호출되는 경우가 존재하는 것으로 추정.

추가로 done 목록 정렬 방향이 `createdAt` 오름차순으로 되어 있어, 최근 완료된 항목이 아래에 쌓이는 문제도 확인됨 (요구사항: 최근 완료 → 위에 표시되어야 함).

### 수정 내용

**1. `handleAdd()` — 예약 시간 미전달 버그 수정 (`ScheduleTab.tsx`)**

`formAt` 입력값이 `entry.scheduledAt`에 전달되지 않아 항상 `null`로 초기화되던 문제 수정:

```typescript
// 수정 전
scheduledAt: null,

// 수정 후
scheduledAt: formAt || null,
```

이로써 `useEffect` 내 `!s.scheduledAt` 필터가 올바르게 동작하여 예약 시간이 있는 항목은 즉시 실행 큐에 포함되지 않음.

**2. done 컬럼 정렬 방향 변경 (`ScheduleTab.tsx`)**

```typescript
// 수정 전 (오름차순)
.sort((a, b) => a.createdAt.localeCompare(b.createdAt))

// 수정 후 (내림차순 — 최근 완료 → 상단)
.sort((a, b) => b.createdAt.localeCompare(a.createdAt))
```

> `ScheduleEntry` 타입에 `finishedAt` 필드가 없으므로 현재는 `createdAt` 기준 내림차순 적용.  
> `finishedAt` 필드 추가 및 running→done 전환 시 타임스탬프 기록은 향후 과제로 남김.

**3. `runScheduleDelay()` 카운트다운 함수 추가 (`useTcRunner.ts`)**

직접 `onStartTest`를 호출하는 경로(칸반 외 경로)에서도 예약 시간을 처리할 수 있도록 유틸 함수 추가:

**추가된 번역 키:**
| 키 | 한국어 | 영문 |
|----|--------|------|
