# 음단절 감지 알고리즘 개선 — Lessons Learned

**작성일:** 2026-04-06  
**검증 기준:** Ground Truth 수동 생성 음원 (철수 5건, 영희 4건 + 정상구간 1건)  
**최종 결과:** 방법1/방법2 모두 Recall 100% · Precision 100%

---

## 1. 발견된 문제와 근본 원인

### 1-1. 짧은 단어 음단절 미검출 ("여보" 170ms)
- **증상:** 철수 첫 대사 "여보세요"에서 "여보" 음단절이 검출되지 않음
- **원인:** `script_gap_detector`의 서브윈도우 방식(200ms dB 평균)이 170ms 묵음을 평균값에 묻어버림
- **해결:** 200ms 서브윈도우를 **10ms raw peak 프레임 스캔**으로 전면 교체  
  (`audio_anomaly_detector` 방식 차용)
- **교훈:** dB 평균 기반 서브윈도우는 윈도우 길이보다 짧은 묵음을 은폐한다. 검출 민감도가 중요한 경우 반드시 프레임 단위 peak 스캔을 사용할 것

---

### 1-2. 문장 끝 음단절이 잘못된 구간에 배정 ("걷자")
- **증상:** 철수 5번 대사 내 "걷자" 음단절이 60.0~63.7s 구간으로 잘못 보고 (실제 위치 70.64~71.06s)
- **원인:** ref 오디오에 대화 흐름 상 자연 포즈(1040ms)가 `SILENCE_GAP_MS=700ms` 임계값을 초과 → VAD가 5번 대사를 seg5(60~63.7s)와 seg6(64.7~71.1s) 두 개로 분절 → 대본 줄수(5)보다 VAD 세그먼트(6)가 많아 6번 인덱스가 `[대본 없음]`으로 처리됨
- **해결:** `n_segs > n_lines`일 때 **인접 세그먼트 간 침묵 갭이 가장 작은 쌍부터 순서대로 병합**하여 `n_lines` 개로 맞춤
  ```python
  while len(segs) > n_target:
      gaps = [segs[i+1][0] - segs[i][1] for i in range(len(segs)-1)]
      min_idx = gaps.index(min(gaps))
      segs = segs[:min_idx] + [(segs[min_idx][0], segs[min_idx+1][1])] + segs[min_idx+2:]
  ```
- **교훈:** 대본을 기반으로 VAD 정렬을 할 때 "자연 포즈도 대사 내부일 수 있다"는 인식이 필요. SILENCE_GAP_MS를 무조건 높이는 것보다 n_segs/n_lines 불일치 시 스마트 병합이 더 안전하다

---

### 1-3. 문장 시작 음단절 미검출 ("응")
- **증상:** 영희 3번 대사 "응, 무조건 우유랑" 에서 "응" (35.68s) 음단절이 방법1에서 검출되지 않음
- **원인:** `_has_prior_activity` 필터가 "직전 1초 이내 test 활성 신호가 있어야 검출"을 요구하는데, 문장 간 포즈에서는 test도 ref도 모두 조용하므로 직전 활성 기록이 없음 → 정상적인 음단절임에도 필터에서 차단됨
- **해결:** `_has_prior_activity`에 `ref_rms` 파라미터 추가. **직전 구간의 ref도 주로 조용했다면** (문장 간 포즈) → test 직전 활성 조건을 면제
  ```python
  if ref_rms is not None:
      pre_ref = ref_rms[pre_start:seg_start_frame]
      if len(pre_ref) == 0 or float(np.mean(pre_ref > speech_strong_rms)) < 0.25:
          return True  # 직전이 자연 포즈였으면 허용
  ```
- **교훈:** "직전 활성 없으면 FP일 것이다" 가정은 문장 시작 음단절에 취약하다. ref 오디오 상태를 함께 확인해야 한다

---

### 1-4. 정상 구간 오탐 (FP 49.33s, 50ms)
- **증상:** 영희 4번 정상 대사(48.7~59.7s) 내 49.33s~49.38s에 50ms 묵음 FP 발생
- **원인:** 슬라이딩 윈도우 청크 경계 정렬 오차로 발생한 아주 짧은 허위 이벤트
- **해결:** `min_anomaly_ms` 기본값을 50ms → **80ms**로 상향
  - 실제 인지 가능한 최소 음단절은 통상 80ms 이상
  - 50ms 이하는 청크 경계 아티팩트일 가능성이 높음
- **교훈:** `min_anomaly_ms`가 너무 낮으면 청크 경계 정렬 오차가 FP로 잡힌다. VoIP 실제 장애 기준 80ms를 기본값으로 권장

---

### 1-5. iOS/Android ref 경로 뒤바뀜
- **증상:** ViSQOL MOS가 iOS 1.284, Android 1.255로 비정상 (정상은 3.0 이상)
- **원인:** CLI 인자 `--ref-path-ios`에 SPEAKER_00(철수=Android용), `--ref-path-android`에 SPEAKER_01(영희=iOS용)이 반대로 지정됨
- **발견 방법:** CC 유사도 교차 비교
  - iOS 녹음 vs SPEAKER_00(철수): 0.03 (거의 무관)
  - iOS 녹음 vs SPEAKER_01(영희): 0.27 (연관)
- **해결:** `--ref-path-ios SPEAKER_01.wav --ref-path-android SPEAKER_00.wav`로 교정
- **교훈:** 분석 전 CC 상호 유사도로 ref-test 매핑이 맞는지 교차 검증할 것. ViSQOL MOS가 1.x대이면 ref 경로 오지정을 먼저 의심하라

## 2. 향후 과제

### 2-1. PLC 은폐형 드롭아웃
- **문제:** 패킷 손실 시 수신단(Android/iOS)이 PLC(Packet Loss Concealment)로 자체 음성 보간하면 완전한 묵음이 아닌 왜곡 신호가 입력됨 → 현재 `digital_zero` 기반 묵음 검출 불가
- **대응 방향:** ratio 기반 gain_drop 방법(깨짐 A/B)으로 보완 가능하나, 별도 PLC 판정 로직이 필요
- **우선순위:** 중

### 2-2. 이중 검출 결과 판정 기준 정형화
- **문제:** 방법1(전역 CC 기반)과 방법2(VAD 구간 기반)가 각각 독립 검출하는데, 한쪽만 검출한 경우의 판정 기준이 불명확
- **대응 방향:** `방법1 AND 방법2 → 확정`, `방법1 OR 방법2 → 의심(Suspect)` 같은 신뢰도 계층 정의
- **우선순위:** 중

### 2-3. VAD SILENCE_GAP_MS 자동 튜닝
- **문제:** `SILENCE_GAP_MS=700ms`는 고정값. 화자/시나리오에 따라 최적값이 달라짐
- **대응 방향:** n_segs/n_lines 불일치 빈도에 따라 자동으로 GAP을 조정하거나, 대본 줄수 기반으로 GAP을 역산
- **우선순위:** 낮음 (현재 스마트 병합으로 우회 가능)

### 2-4. 연속 드리프트 누적 대응
- **문제:** 다수 음단절 발생 시 누적된 시간 오프셋 드리프트가 후반부 정렬 정확도를 저하시킬 수 있음
- **대응 방향:** 슬라이딩 윈도우 cursor 제한을 현재 ±500ms에서 더 세밀하게 조정, 또는 DTW 기반 정렬 도입
- **우선순위:** 낮음 (6초 청크 × 슬라이딩으로 현재 충분히 보정됨)
