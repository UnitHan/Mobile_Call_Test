## 1. 마일스톤 이메일 발송 미작동 수정

500건 단위 마일스톤 이메일이 2,400회 장기 테스트 기간 내내 한 번도 발송되지 않은 문제를 수정한다.

### 1-1. Keychain SMTP 앱 비밀번호 등록

**현상**: macOS Keychain에 `smtp-app-password`가 미등록 → `get_secret` 호출 시 `null` 반환 → 이메일 발송 건너뜀

**조치**: 터미널에서 직접 등록

```bash
security add-generic-password \
  -s "com.qabulls.call" \
  -a "smtp-app-password" \
  -w "<Gmail 앱 비밀번호 16자리>" \
  -U
```

> `MILESTONE_EMAIL_PANEL`은 보안상 `false` 유지 (UI에 SMTP 설정 패널 노출하지 않음). 발송 로직은 UI 패널 설정과 무관하게 독립 동작.

### 1-2. `localStorage.setItem` 위치 이동 — 발송 성공 후로

**파일**: `src/hooks/useTcRunner.ts`  
**함수**: `checkMilestoneAndSendEmail()`

**현재 (문제)**:
```
milestone 달성 확인
→ localStorage에 마킹 (소비)     ← 여기서 기회 소진
→ 엑셀/JSON 생성
→ SMTP 비밀번호 조회 → 없음 → return (이메일 미발송)
```

**수정 후**:
```
milestone 달성 확인
→ 엑셀/JSON 생성
→ SMTP 비밀번호 조회 → 없음 → return (이메일 미발송, 마킹 안 됨)
→ 이메일 발송 성공
→ localStorage에 마킹 (소비)     ← 성공 확인 후에만 소비
```

→ 실패 시 다음 TC 결과 적재 때 **자동 재시도** 가능

### 1-3. 소급 발송 — 이미 소비된 마일스톤 처리

현재 DB 2,356건+ → 500·1,000·1,500·2,000 총 **4건의 마일스톤 이메일 누락** 상태.

**조치**: 수정 1-1 + 1-2 적용 후, DevTools Console에서:
```javascript
localStorage.setItem("ixio-milestone-last-notified", "0");
```
→ 다음 TC 결과 적재 시 `milestone = 2000` 도달 → 2,000회 메일 1건 발송

> 500·1,000·1,500 개별 발송이 필요하면 별도 소급 로직 추가 검토

## 2. ERROR 건 디버깅 로그 보강

2,400회 장기 테스트에서 **622건 (28.1%) ERROR** 발생. 전부 `"테스트 실패: "` (빈 에러 메시지)로 원인 추적 불가.

### 분석 결과 — 두 가지 에러 유형

| 유형 | 소요 시간 | 영향 범위 | 건수 | 패턴 |
|------|----------|----------|------|------|
| **A (짧은 에러)** | 37~50초 | TC_01 + TC_02 동시 | 526건 | 특정 시점부터 수십 회차 연속 → 자연 복구 |
| **B (긴 에러)** | 170~195초 | TC_01만 (TC_02 PASS) | 102건 | 연속 블록 + 가끔 산발 |

**유형 A 추정**: Appium 세션 타임아웃 / 단말 연결 실패 → Python 스크립트가 stderr 없이 non-zero exit  
**유형 B 추정**: iOS→Android 방향 통화 연결 또는 녹음 타임아웃 → 정상 대비 40~60초 추가 대기 후 실패

### 2-1. Rust — `test_cmd.rs` 에러 반환부 로그 보강

**파일**: `src-tauri/src/test_cmd.rs`

현재:
```rust
Err(format!("테스트 실패: {}", stderr_output))  // stderr_output이 빈 문자열
```

추가할 정보:
- **Python exit code** 포함
- stderr가 빈 문자열일 때 **stdout 마지막 N줄** 포함 (Python이 stdout에만 에러 출력했을 가능성)
- `"테스트 실패: "` 대신 `"테스트 실패 (exit={code}): {stderr 또는 stdout 끝부분}"` 형식

### 2-2. Python — `ixio_automated_test.py` 예외 처리 보강

**파일**: `src-tauri/scripts/ixio_automated_test.py`

추가할 정보:
- 실패한 **단계** 명시 (Appium 연결 / 통화 발신 / 수신 대기 / 녹음 시작 / 녹음 대기 / 분석)
- **exception traceback**을 stderr에 출력
- 타임아웃 발생 시 **어떤 타임아웃인지** (Appium session creation / call connection / recording) 명시
- 현재 silent exit하는 경로에 `sys.stderr.write()` 또는 `traceback.print_exc()` 추가
