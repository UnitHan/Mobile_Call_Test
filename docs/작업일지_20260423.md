## 원인 분석

### 핵심 원인: WDA page_source 과폴링

CallKit PiP가 활성화되면 iOS XCUITest(WDA)는 `page_source` / `find_element` 호출마다 **전체 accessibility snapshot을 재생성**해야 한다. 통화 타이머가 매초 변경되므로 WDA 내부 snapshot 재생성 큐가 포화 상태가 되어 약 47초 시점에 크래시 → Python 프로세스 block.

**통화 연결 직후 WDA 요청 빈도 (수정 전)**:

| 스레드 | 폴링 간격 | 60초 기준 총 요청 |
|--------|----------|-----------------|
| `_wait_ios_timer_00_for_trigger` (main) | 100ms | ~50회/5s |
| `_check_sp1` 스레드 `wait_for_call_connecting_state` | 200ms | ~300회/60s |
| `_tap_video_call_popup` iOS loop | 500ms | ~50회 |

→ 통화 연결 직후 10회/s 이상 page_source 요청 → WDA 47초 시점 크래시

### 이전 환경에서 미발생한 이유
iOS 버전 또는 WDA 버전에 따라 CallKit PiP 오버레이가 XCUITest accessibility tree에 포함되지 않아 snapshot 재생성 비용이 낮았던 것으로 추정.

## 추가 이슈: iPhone 화면 잠금으로 인한 앱 재실행 실패

### 현상
테스트 루프 중 iPhone 화면이 꺼지면 `activate_app` 실패:
```
Unable to launch com.lguplus.aicallagent because the device was not, 
or could not be, unlocked.
```

### 수정: `ios_call_handler.py` — `_ios_wake_screen` 헬퍼 추가

```python
@staticmethod
def _ios_wake_screen(driver) -> None:
    """iPhone 화면이 꺼져 있으면 깨웁니다 (activate_app 전 필수 호출)."""
    try:
        driver.execute_script('mobile: unlock')
    except Exception:
        pass
```

모든 `activate_app` 호출 전에 `_ios_wake_screen(driver)` 삽입:
- `open_keypad_iphone` → Step 0 (activate_app 전)
- `open_keypad_iphone` → Step 4 재시작 (terminate 후 activate_app 전)
- 키패드 복구 루프 내 재시작
- `tc_base.py` `_relaunch_ixio_speaker1()` / `_relaunch_ixio_speaker2()` 내 iOS activate_app 전
