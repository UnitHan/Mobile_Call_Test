## 3. 핵심 장애물 및 해결 방안

### 장애물 1: Appium iOS 서버 하나만 존재

**문제**: `appium_server_ios` 하나로 두 iPhone 운용 시 세션 충돌.

**해결**: iOS-iOS 조합 감지 시 Android 포트 슬롯을 iOS sp1으로 재활용.
```
iOS-iOS 시 포트 재할당:
  sp1(발신) → appium_server_android 포트 (기존 4725/4727)
  sp2(수신) → appium_server_ios 포트 (기존 4726/4728)
```
Rust/프론트 변경 없이 Python 레이어에서만 처리.

### 장애물 2: WDA 포트 충돌

**문제**: 두 iPhone 모두 WDA port 8100 사용 시 포트 충돌.

**해결**: 역할별 WDA 포트 분리.
```
speaker1 iOS: wdaLocalPort=8100, mjpegServerPort=9100
speaker2 iOS: wdaLocalPort=8200, mjpegServerPort=9200
```

### 장애물 3: IosWdaManager 단일 인스턴스 문제

**문제**: WDA IP 캐시(`_cached_iphone_ip`)가 한 기기만 추적.

**해결**: iOS-iOS 시 `wda_manager_sp2` 두 번째 인스턴스 생성.
- `AppiumDeviceSetup`에 `wda_manager_sp2` 파라미터 추가
- sp2 iOS 연결 시 `wda_manager_sp2.find_wda_url()` 사용

### 장애물 4: `phase_answer_ios_sp2`의 Android `_phase_active_event` 의존

**문제**: iOS-iOS 시 `_phase_active_event = None` → and-only 로직 통과 불가.

**분석**: 현재 코드의 `else` 브랜치:
```python
else:
    self.answer_call_on_speaker2()     # iOS 5단계 수신 전략 (이미 구현됨)
    call_connected = self.wait_for_call_connecting_state()  # iOS UI 타이머 감지
```
이 경로가 iOS-iOS에서도 동작함 → 단, PreWarm(병렬 subprocess) 지원 추가 필요.

**해결**: `phase_answer_ios_sp2`에 iOS-iOS PreWarm 경로 추가.
- `_phase_active_event is None` 시 `prepare_audio_players()` 호출
- 별도 `phase_start_ios_sp2_watcher` 불필요 (answer_call_on_speaker2 자체 폴링 방식)

### 장애물 5: `ios_udid` 단일 기기 문제

**문제**: `ixio_automated_test.py`에서 `ios_udid`가 첫 번째 iOS만 선택.

**해결**: iOS-iOS 시 `ios_udid = speaker1_device`(primary), sp2는 `wda_manager_sp2`로 독립 관리.

## 4. 구현 범위

### 변경 파일

| 파일 | 변경 내용 |
|---|---|
| `ixio_automated_test.py` | iOS-iOS 감지 → sp1용 서버 재할당, `wda_manager_sp2` 생성, `AppiumDeviceSetup` 전달 |
| `appium_device_setup.py` | `wda_manager_sp2` 파라미터, `appium_server_sp1_ios` 추가, 역할별 WDA 포트/서버 분기 |
| `tc_base.py` | `phase_answer_ios_sp2` iOS-iOS PreWarm 추가, `phase_call_from_ios` sp2=iOS 시 iOS 수신 watcher 시작 |
| `tc_01~04.py` | sp2=iOS 시 `phase_start_ios_sp2_watcher` 호출 (PreWarm) |

### 변경 없는 파일

- `ios_wda_manager.py` — 두 인스턴스 각각 독립 동작
- Rust 소스 (`test_cmd.rs`, `state.rs`, `appium_cmd.rs`) — 포트 재활용으로 무변경
- `ios_call_handler.py`, `android_call_handler.py` — 수정 없음

## 7. 알려진 제약

- **두 iPhne 동일 WiFi 필수**: WDA IP 자동 탐지가 WiFi 기반
- **두 WDA 동시 실행**: 각 iPhone에서 WDA 앱이 실행 중이어야 함
- **Appium XCUITest 세션 격리**: 두 Appium 포트로 완전 격리되므로 세션 간섭 없음

- **iOS 26.4 beta**: WDA 빌드 배포 타겟 16.0 패치 유지 (setup_wda_iphone.sh 처리 중)
