## 1. 파형 정렬(Offset) 버그 수정

### 문제 발견
- 4/2 오전 TC_01 테스트 보고서(`hybrid_report_1775090664.html`) 검증 중 **파형 정렬이 크게 밀리는 현상** 확인
- Android 오프셋: `+3.020s` (실제 `-0.638s`이어야 함) → **3.66초 오차**
- iOS 오프셋: `-2.320s` (실제 `-1.427s`이어야 함) → **0.89초 오차**
- 이로 인해 음단절 탐지 위치가 전부 잘못 잡힘

### 원인 분석
- `global_offset_sec()` 함수가 **에너지 봉투(dB) 기반 cross-correlation**을 사용
- VoIP 코덱 왜곡으로 에너지 패턴에 **허위 상관 피크**가 발생
- 에너지 xcorr 상위 10개 후보 중 `+3.020s`(corr=3.9955)가 1위였으나, 실제로는 잘못된 위치

### 수정 내용

#### (1) `script_gap_detector.py` — `global_offset_sec` 함수
| 항목 | 변경 전 | 변경 후 |
|------|---------|---------|
| 입력 | `(ref_db, test_db, frame_sec)` | `(ref_audio, test_audio, sr)` |
| 알고리즘 | 에너지 봉투 dB xcorr | **원본 파형 FFT xcorr** |
| 호출부 (L313) | `global_offset_sec(ref_db, test_db, fsec)` | `global_offset_sec(ref_audio, test_audio, sr)` |

#### (2) `gap_detector.py` (Tauri 앱 scripts) — `find_offset_frames` 함수
| 항목 | 변경 전 | 변경 후 |
|------|---------|---------|
| 입력 | `(ref_db, test_db, max_offset_frames)` | `(ref_audio, test_audio, sr, max_offset_sec)` |
| 알고리즘 | 에너지 봉투 dB xcorr | **원본 파형 FFT xcorr** |
| `detect_gaps_envelope` | 에너지만 사용 | `ref_audio`, `test_audio`, `sr` 파라미터 추가 |
| `analyze()` 호출부 | 에너지만 전달 | `ref_audio=ref_audio, test_audio=test_audio, sr=ref_sr` 추가 |

### 검증 결과

## 2. TC_02 화자 재생 싱크 수정

### 문제
- TC_02 테스트 시 화자1과 화자2의 음원 재생 타이밍이 **서로 안 맞는 현상**
- 원인: 두 화자가 별도 subprocess로 재생되는데, 각 프로세스의 초기화 시간(Python 기동 + import + 파일 로드 + 장치 열기)이 서로 달라 **100~500ms+ 차이** 발생

### 수정 내용 — `play_at` 동기화 메커니즘 도입

#### 수정 파일 3개

**① `audio_playback_mixin.py`**
- `play_at = time.time() + 3.0` 계산 (초기화 여유 시간)
- 두 워커에 동일한 `play_at` 전달

**② `audio_handler.py`**
- `play_audio_to_device()`에 `play_at` 파라미터 추가
- subprocess 명령에 `--play-at` 인자 전달

**③ `audio_player_worker.py`**
- `--play-at` CLI 인자 파싱
- `play()` 함수에 `play_at` 파라미터 추가
- OutputStream 열기 직후, `play_at` 시각까지 `time.sleep()` 대기 → 동시 재생 시작

### 동작 원리
```
T+0ms     부모가 play_at = now + 3초 계산
T+1ms     워커1 subprocess 시작 (초기화 ~800ms)
T+2ms     워커2 subprocess 시작 (초기화 ~600ms)
T+600ms   워커2 초기화 완료 → play_at까지 2.4초 대기
T+800ms   워커1 초기화 완료 → play_at까지 2.2초 대기
T+3000ms  둘 다 동시에 재생 시작 (오차 ~1ms 이내)
```

## 10. UiAutomator2 크래시 근본 원인 분석 및 구조 개선

### 근본 원인
**8개 이상의 Python 스레드**가 동기화 없이 동일한 Appium WebDriver 객체에 동시 접근하여 UiAutomator2(단일 스레드 서비스)에 경쟁 조건(Race Condition) 발생

| 스레드 | 작업 | 빈도 |
|---|---|---|
| `_start_android_caller_active_watcher` | `driver.page_source` | 150ms |
| `_tap_video_call_popup` × 2~3개 | `driver.page_source` + `clickGesture` | 500ms |
| `_detect_vishing_popup` × 2개 | `driver.page_source` | 1500ms |
| Main: `answer_call_on_speaker2` | `driver.find_element()` | 연속 |
| Main: `wait_for_audio_completion` | ADB dumpsys × 3 | 1000ms |

### 해결 — 4가지 구조 개선

#### ① ThreadSafeDriver 래퍼 도입 (`thread_safe_driver.py` 신규)
- `threading.RLock()`으로 모든 드라이버 호출을 직렬화하는 프록시 래퍼
- `page_source`, `find_element()`, `execute_script()` 등 모든 호출이 Lock 통과
- `setup_device()`에서 `driver = ThreadSafeDriver(driver)` 한 줄로 적용
- 기존 코드 변경 최소화 (드롭인 래퍼)

#### ② 중복 팝업 감지 스레드 통합
- **기존**: 같은 디바이스에 2~3개 스레드가 동시에 `_tap_video_call_popup()` 실행
- **수정**: 디바이스당 최대 1개 스레드만 실행
  - TC_01: Android speaker2만 1개 스레드 (iOS speaker1은 `_check_sp1`에서 처리)
  - TC_02: Android speaker1만 1개 스레드 (iOS speaker2는 `_do_answer`에서 처리)

#### ③ 워처에서 driver.page_source 폴링 제거 (`android_call_handler.py`)
- `_start_android_caller_active_watcher()`에서 `_is_call_active_android_ui(driver)` 호출 완전 제거
- ADB `dumpsys telephony/telecom`만 사용 → UiAutomator2 부하 제로
- 폴링 간격 150ms → 500ms로 완화

#### ④ Appium 설정 최적화 (`appium_device_setup.py`)
- `forceAppLaunch: True → False` — 세션 생성 시 앱 강제 재시작 방지
- `shouldTerminateApp: False` — 비의도적 앱 종료 방지  
- `disableWindowAnimation: True` — UI 반응 속도 향상
- `ignoreUnimportantViews: True` — `page_source` XML 크기 축소, 속도 향상

#### ⑤ UiAutomator2 서버 TC 시작 시 강제 초기화 (`appium_device_setup.py`)
- Appium 세션은 매 TC마다 `quit()` → 재생성으로 초기화되지만, 디바이스에 상주하는 **UiAutomator2 서버 프로세스**는 이전 것이 그대로 남아있을 수 있음
- 크래시 후 좀비 상태로 남은 프로세스가 새 세션에서도 문제를 일으킴
- **`_adb_reset_uiautomator2()`** 메서드 추가 — `setup_device()` 진입 시 Appium 세션 생성 전에 호출
  - `am force-stop io.appium.uiautomator2.server`
  - `am force-stop io.appium.uiautomator2.server.test`
  - `pkill -f uiautomator` (좀비 프로세스 정리)
  - 0.5초 대기 후 Appium이 깨끗한 UiAutomator2를 새로 기동

#### ⑥ Android 화면 꺼짐 방지 3중 보강 (`appium_device_setup.py`, `ixio_automated_test.py`)
- **문제**: Wi-Fi ADB 연결 시 `stay_on_while_plugged_in=7`이 무효 (물리적 충전 필요), 테스트 중 화면 OFF → 키 입력 불가로 TC 실패
- **원인**: 기존 `_adb_keep_screen_on()`이 `screen_off_timeout` + `stay_on_while_plugged_in`만 설정 — 충전 중이 아닌 Wi-Fi ADB에서는 후자가 동작하지 않고, 이미 꺼진 화면을 깨우는 로직도 없었음
- **수정**:
  1. `svc power stayon true` 추가 — USB 연결 여부와 무관하게 화면 유지
  2. **`_adb_wake_screen()`** 신규 메서드 — `dumpsys power`로 `state=OFF` / `mWakefulness=Asleep` 감지 시:
     - `KEYCODE_WAKEUP`으로 화면 강제 켜기
     - `input swipe` 잠금화면 해제 (swipe up)
     - `KEYCODE_MENU` 추가 해제 시도
  3. `setup_device()`에서 UiAutomator2 리셋 직후, Appium 세션 생성 **전에** `_adb_keep_screen_on()` 선제 호출
  4. `ixio_automated_test.py` — 익시오 앱 종료→재실행 직전에 `_adb_wake_screen()` 호출

#### ⑦ TC_02 Android 발신단 ADB 경합 해소 (`ixio_automated_test.py`, `android_call_handler.py`)
- **문제**: TC_02에서 Android speaker1 키패드 열기(Appium) 중에 발신워쳐 스레드가 동시에 ADB 폴링 → 같은 Wi-Fi ADB 기기에 대한 ADB 경합 발생
  - `adb: device '192.168.219.103:5555' not found` → UiAutomator2 크래시 → 키패드/번호 입력 전체 실패
  - TC_01은 speaker1=iOS(WDA)이므로 ADB 경합 없음, TC_02만 발생
- **수정**:
  1. **워처 시작 시점 변경** — 키패드 열기 완료 **후**, `make_call()` 직전에 워처 스레드 시작 (ADB 경합 제거)
  2. **`open_ixio_keypad()` 화면 깨우기** — 앱 재시작 전에 `_adb_wake_screen()` 호출
  3. **Appium 실패 시 ADB 폴백** 추가:
     - `terminate_app()` 실패 → `adb shell am force-stop` 폴백
     - `activate_app()` 실패 → `adb shell monkey` 폴백
     - 키패드 탭 실패 → `_tap_element_adb()` (uiautomator dump + input tap) 폴백

#### ⑧ TC_02 통화 연결 직후 끊김 수정 (`android_call_handler.py`, `ixio_automated_test.py`)
- **문제**: TC_02(speaker1=Android, speaker2=iOS)에서 통화 연결 직후 Android가 끊어짐
- **원인**: `_start_android_caller_active_watcher` Phase 0이 워쳐 스레드에서 `make_call()`과 **동시 실행**
  - VoIP 앱(ixiO)은 **발신만으로도** `IN_COMMUNICATION` 오디오 모드 설정
  - Phase 0: `_is_call_active_android()` check ④가 `IN_COMMUNICATION` 감지 → "잔류 ACTIVE"로 오판
  - 15초 후 `KEYCODE_ENDCALL` 전송 → 실제로는 **새 통화를 종료**
  - TC_01은 speaker1=iOS라서 이 워쳐 자체가 없어 문제 없음
- **수정**:
  1. Phase 0를 **`_ensure_android_idle()`** 별도 메서드로 분리 (동기 실행)
  2. `ixio_automated_test.py`에서 **`make_call()` 전에 동기적으로** `_ensure_android_idle()` 호출
  3. 워쳐 스레드는 Phase 1(ACTIVE 감지)만 실행 → ENDCALL 없음
  - 실행 순서: `open_ixio_keypad()` → `_ensure_android_idle()` (동기) → 워쳐 시작 → `make_call()`

## 12. UiAutomator2 크래시 — 빠른 실패 + Appium 자동 재초기화 (`android_call_handler.py`, `ixio_automated_test.py`)

### 문제
- UiAutomator2 크래시 발생 시, 현재 회차에서 모든 후속 Appium 작업이 실패하며 무의미하게 시간 소모
  - `terminate_app` 실패 → `activate_app` 실패 → 키패드 탭 실패 → 11자리 번호 입력 전부 실패 → 발신 버튼 실패 → 60초 타임아웃
- 기존에 mid-test 세션 복구(`_recover_appium_session()`)를 시도했으나 복잡도 대비 효과 미미

### 해결 — "빠른 실패(Fail Fast)" 전략
- **원리**: Rust 측 `ensure_appium_running()`이 이전 테스트 실패 시(`PREV_TEST_COMPLETED_OK=false`) 이미 Appium 서버 전체를 재시작(`pkill -f appium` → `adb kill-server` → 재기동)
- 따라서 mid-test 복구 대신 **즉시 현재 회차를 중단**하고 자동 재시도 메커니즘에 맡기면 깨끗한 Appium 환경에서 재시작됨

### 수정 내용

#### ① `open_ixio_keypad()` — 크래시 감지 시 `'uia2_crash'` 리턴
- `terminate_app()` / `activate_app()` 실패 메시지에서 UiAutomator2 크래시 패턴 감지:
  - `'not found'`, `'instrumentation'`, `'ECONNRESET'`, `'socket hang up'`
- 크래시 감지 시 `return 'uia2_crash'` → ADB 폴백으로 앱은 살려두되 테스트는 즉시 중단

#### ② `ixio_automated_test.py` — `'uia2_crash'` → `'crash'` → `sys.exit(3)`
```python
_keypad_result = self.open_ixio_keypad('speaker1')
if _keypad_result == 'uia2_crash':
    return 'crash'  # → sys.exit(3) → Rust: Appium 전체 재시작 후 재시도
```

#### ③ `_recover_appium_session()` 제거
- mid-test 세션 복구 시도 자체가 불필요해짐 → 메서드 삭제

#### ④ `make_call()` 간소화 + ADB 발신 폴백
- 숫자 입력 중 `socket hang up`/`ECONNRESET` 감지 → 즉시 ADB `input keyevent`로 전환 (세션 복구 시도 없음)
- **발신 버튼 ADB 폴백 추가**: Appium 발신 실패 시 `_tap_element_adb(udid, '전화')` / `'통화'`로 탭

### Appium 자동 재초기화 흐름 (Rust `ensure_appium_running`)
```
TC 실패 → PREV_TEST_COMPLETED_OK = false
  → 다음 회차 시작 시:
    1. pkill -f appium         (Appium Node 서버 종료)
    2. adb kill-server         (ADB 서버 종료)
    3. adb start-server        (ADB 재시작)
    4. adb connect <Wi-Fi IP>  (무선 기기 재연결)
    5. Appium 서버 재기동 (4723, 4724)
    6. Python 새 프로세스 → setup_device() → _adb_reset_uiautomator2() → 새 세션
```

## 14. UiAutomator2 크래시 방지 — Appium 코드 전면 점검 (`android_call_handler.py`, `call_state_mixin.py`, `ixio_automated_test.py`, `appium_device_setup.py`, `test_cmd.rs`)

### 근본 원인 분석
- TC_02 로그에서 **`terminate_app` / `activate_app` 모두 성공**했는데, **4초 후 `find_element`에서 UiAutomator2 크래시** 발생
- 이 시점에 Android driver를 동시 접근하는 다른 스레드가 없으므로 race condition이 아님
- 크래시 원인: ① 앱 재시작 후 VoIP 초기화 부하로 instrumentation 불안정 ② TC_01→TC_02 전환 시 Appium 서버(4725)가 재사용되어 이전 세션 잔류물 영향

### 발견된 추가 위험 요소

| # | 위험도 | 문제 | 파일 |
|---|--------|------|------|
| 1 | Critical | `_clear_dial_field_android()` 최대 20×5=100회 `find_element` tight loop (0.15s) | android_call_handler.py |
| 2 | Critical | `activate_app()` 후 UiAutomator2 health check 없음 | android_call_handler.py |
| 3 | Critical | TC 모드 실패 후 Appium 서버 재시작 안 됨 (포트 alive면 건너뜀) | test_cmd.rs |
| 4 | High | iOS 타이머 워처 10Hz `page_source` 폴링 (0.05~0.1s 간격) | call_state_mixin.py |
| 5 | Medium | 보이스피싱 워커에서 UiAutomator2 크래시 시 무한 반복 | ixio_automated_test.py |
| 6 | Medium | Android caps에 `skipUnlock`/`autoGrantPermissions` 미설정 | appium_device_setup.py |

### 수정 내용

#### ① `_clear_dial_field_android()` 부하 감소
- 반복 횟수: 20회 → 5회 (앱 재시작 후 잔류가 5자리 이하)
- 클릭 후 대기: `0.15s` → `0.3s`
- `instrumentation` 에러 감지 시 즉시 return (죽은 세션에 반복 요청 방지)

#### ② `open_ixio_keypad()` UiAutomator2 health check 추가
- `activate_app()` 후 대기: 4초 → 5초 (VoIP 초기화 여유)
- 대기 후 `driver.current_activity` 호출로 instrumentation 생존 확인
- 크래시 감지 시 `'uia2_crash'` 즉시 리턴
- Step 1 키패드 탭에서도 `instrumentation`/`not running` 패턴 감지 → `'uia2_crash'` 리턴

#### ③ `make_call()` 숫자 입력 ADB 폴백 보강
- 첫 번째 숫자부터 버튼을 못 찾으면 즉시 남은 전체 번호를 `adb input keyevent`로 전환
- 기존: 11번 반복해서 못 찾음 → 개선: 첫 실패 시 즉시 ADB 전환

#### ④ TC 모드 Appium 강제 재시작 (Rust `test_cmd.rs`)
- **기존**: `ensure_tc_appium_running()` — 포트가 살아있으면 재시작 안 함 → UiAutomator2만 죽어도 Appium 서버는 정상이라 그대로 재사용
- **수정**: `PREV_TEST_COMPLETED_OK = false`이면 `kill_port(4725)` + `kill_port(4726)` → `ensure_tc_appium_running()`으로 **강제 재시작**
- `kill_port` 가시성: `fn` → `pub(crate) fn` (test_cmd.rs에서 호출 가능)

#### ⑤ iOS 타이머 워처 폴링 간격 완화 (`call_state_mixin.py`)
- burst 폴링: `0.05s` → `0.15s`
- 기본 폴링: `0.1s` → `0.5s`

#### ⑥ 보이스피싱 워커 크래시 즉시 중단 (`ixio_automated_test.py`)
- `instrumentation`/`not running` 에러 감지 시 즉시 `return False, None`

#### ⑦ Android capabilities 안정화 (`appium_device_setup.py`)
- `skipUnlock: True` — 세션 생성 시 잠금해제 시도 제거 (불필요한 ADB 부하)
- `autoGrantPermissions: False` — 권한 팝업 자동 처리 비활성화 (이미 허용됨)
