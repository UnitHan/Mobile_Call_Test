## ISS-001: ixi-O 배너 배치 반복 수정 (16회+)

| 항목 | 내용 |
|------|------|
| **심각도** | Low (UI) |
| **영향 범위** | `DeviceSection.tsx`, `App.css` |
| **소요 시간** | 장시간 (16회+ 반복 수정) |
| **상태** | ✅ 해결됨 |

### 증상

DeviceSection 패널 내에 ixi-O 광고 배너 이미지를 배치하는 작업에서 원하는 위치에 정확히 놓이지 않는 문제가 반복 발생.

### 시도한 방법들

| 시도 | 접근 방식 | 결과 |
|------|-----------|------|
| 1~5회 | 버튼 아래 수직 배치 | ❌ 카드 높이 증가, 레이아웃 깨짐 |
| 6~10회 | absolute / relative 포지셔닝 | ❌ 다른 요소와 겹침 |
| 11~14회 | flex 세부 조정 | ❌ 반응형 문제 |
| 15~16회 | **수평 레이아웃 전환** | ✅ 성공 |

### 근본 원인

카드 내부에 이미지를 수직으로 추가하면 카드 전체 높이가 변하면서 CSS Grid 레이아웃에 연쇄 영향을 미침.

### 최종 해결

```
기존: 버튼들 (수직)
      배너 (수직)

변경: .device-lower (flex row)
      ├── .device-buttons (왼쪽)
      └── .ixio-banner-wrap (오른쪽)
```

```css
.device-lower {
  display: flex;
  align-items: flex-start;
  gap: 16px;
}
.ixio-banner-wrap {
  margin-top: 10px;
}
.ixio-banner {
  filter: brightness(0.7) contrast(0.9);  /* 다크 테마 조화 */
}
```

### 교훈

- CSS Grid 레이아웃 내부에서 수직 요소 추가 시 전체 레이아웃 연쇄 영향 주의
- 수평 배치가 카드 높이 변경 없이 안전
- 디자인 방향이 안 맞으면 전체 레이아웃 구조를 재검토하는 것이 빠름 (micro-fix 반복 지양)

## ISS-002: Rust i32/i64 타입 불일치

| 항목 | 내용 |
|------|------|
| **심각도** | Critical (컴파일 에러) |
| **영향 범위** | `test_cmd.rs` |
| **소요 시간** | 짧음 |
| **상태** | ✅ 해결됨 |

### 증상

`test_cmd.rs`에 날짜별 보고서 폴더 기능 추가 후 컴파일 에러 발생:

```
error[E0308]: mismatched types
  --> src/test_cmd.rs:639:21
   |
   | let y = y + (mi + 2) / 12;
   |             ^^^^^^^^^^^^^^ expected `i32`, found `i64`

error[E0277]: cannot add `i64` to `i32`
```

### 근본 원인

날짜 계산 코드에서 `y`를 `as i32`로 캐스팅한 후, `mi`는 `i64` 연산 결과로 남아 있어 타입 불일치 발생.

```rust
// 문제 코드
let y = (10000 * (4 * days + 2) / 1461001) as i32;  // ← i32
let mi = (100 * doy + 52) / 3060;                    // ← i64
let y = y + (mi + 2) / 12;                           // ← i32 + i64 = ERROR
```

### 해결

전체 날짜 계산을 **Howard Hinnant의 Civil Calendar 변환 알고리즘**으로 교체.  
모든 연산을 `i64`로 통일하여 타입 캐스팅 이슈 제거.

```rust
// 해결 코드 (모두 i64)
let z = days + 719468;
let era = z / 146097;
let doe = z - era * 146097;
let yoe = (doe - doe / 1460 + doe / 36524 - doe / 146096) / 365;
let y = yoe + era * 400;
let doy = doe - (365 * yoe + yoe / 4 - yoe / 100);
let mp = (5 * doy + 2) / 153;
let d = doy - (153 * mp + 2) / 5 + 1;
let m = if mp < 10 { mp + 3 } else { mp - 9 };
let y = if m <= 2 { y + 1 } else { y };
```

### 교훈

- Rust는 정수 타입 간 암묵적 변환을 허용하지 않음 — 모든 산술 연산에서 타입 일관성 유지 필요
- 복잡한 날짜 계산 시 검증된 알고리즘(Howard Hinnant) 사용 권장
- `chrono` 크레이트 도입을 고려할 수 있으나, 의존성 최소화를 위해 순수 연산 선택

## ISS-003: 다크 테마 라이선스 UI 가시성

| 항목 | 내용 |
|------|------|
| **심각도** | Medium (UX) |
| **영향 범위** | `SettingsModal.tsx`, `App.css` |
| **소요 시간** | 중간 |
| **상태** | ✅ 해결됨 |

### 증상

오픈소스 라이선스 탭 추가 후, 다크 테마에서 텍스트가 보이지 않는 문제:
- 라이선스 본문이 어두운 배경과 같은 색
- 패키지 버전 태그가 안 보임
- 드롭다운 카운트 배지가 안 보임

### 해결

```css
/* 버전 태그 + 라이선스 본문 */
.lic-ver, .lic-text { color: #ffffff; }

/* 패키지 카운트 배지 */
.lic-count { color: #8ab4f8; }  /* 밝은 파란색 */

/* 라이선스 그룹 배경 */
.lic-group { background: rgba(255,255,255,.05); }
```

### 교훈

- 다크 테마 UI 개발 시 모든 텍스트/배경 조합에서 **콘트라스트 비율**(WCAG 4.5:1 이상) 확인 필요
- 새 컴포넌트 추가 시 기존 CSS 변수(`--text`, `--bg-card`)를 우선 활용

## ISS-004: HDMI 인덱스 드리프트

| 항목 | 내용 |
|------|------|
| **심각도** | High (기능 오류) |
| **영향 범위** | CONNECT 6 라우팅 진단 |
| **소요 시간** | 중간 |
| **상태** | ✅ 해결됨 |

### 증상

CONNECT 6 사운드카드 진단 시 HDMI 인덱스가 세션 간에 변동(drift)하여 잘못된 채널에 오디오가 라우팅됨.

### 근본 원인

macOS Core Audio에서 USB 오디오 장치의 인덱스가 연결 순서/타이밍에 따라 변할 수 있음. HDMI 출력이 포함된 경우 인덱스 offset이 추가로 발생.

### 해결

`diagnose_connect6.py`에서 인덱스 기반이 아닌 **장치 UID 기반** 매칭으로 전환하여 드리프트 문제 해소.

### 교훈

- USB 오디오 장치의 인덱스는 불안정 — 항상 고유 ID(UID) 기반으로 참조
- macOS Core Audio API에서 `kAudioDevicePropertyDeviceUID` 사용 권장

## ISS-005: TC_03 음원 중간 정지

| 항목 | 내용 |
|------|------|
| **심각도** | High (테스트 실패) |
| **영향 범위** | `ixio_automated_test.py`, `audio_handler.py` |
| **소요 시간** | 중간 |
| **상태** | ✅ 해결됨 |

### 증상

보이스피싱 TC(TC_03)에서 음원 재생이 통화 중간에 정지됨. TC_01(일반 통화)에서는 정상.

### 근본 원인

TC_03에서는 보이스피싱 경고 팝업이 표시되면서 앱 포커스가 변경됨. 이로 인해 음원 재생 스레드와 Appium UI 제어 스레드 간 타이밍 충돌 발생.

### 해결

음원 재생을 별도 워커 스레드(`audio_player_worker.py`)로 분리하고, 통화 상태 변경과 독립적으로 동작하도록 구조 변경.

### 교훈

- 음원 재생과 UI 자동화는 반드시 별도 스레드로 분리
- 보이스피싱 TC는 앱 포커스 변경이 발생하므로 추가적인 동기화 고려 필요

## ISS-006: iOS 거짓양성 감지

| 항목 | 내용 |
|------|------|
| **심각도** | Medium (분석 정확도) |
| **영향 범위** | `html_report.py`, 음단절 분석 |
| **소요 시간** | 중간 |
| **상태** | ✅ 해결됨 |

### 증상

iOS 녹음에서 음단절이 없는데도 **거짓양성(false positive)**으로 음단절 감지되는 경우 발생.

### 근본 원인

iOS 녹음 시작/종료 시점에 짧은 무음 구간이 존재하며, 이를 음단절로 오인.

### 해결

HTML 리포트 생성 시 **녹음 시작/종료 N초** 구간을 분석 제외 범위로 설정하여 거짓양성 필터링.

### 교훈

- 녹음 파일의 시작/끝 구간은 시스템 지연으로 무음이 포함될 수 있음
- 분석 대상 구간을 명확히 정의하여 edge case 제거

## ISS-007: 설정 모달 탭 오버플로

| 항목 | 내용 |
|------|------|
| **심각도** | Low (UI) |
| **영향 범위** | `SettingsModal.tsx`, `App.css` |
| **소요 시간** | 짧음 |
| **상태** | ✅ 해결됨 |

### 증상

오픈소스 라이선스 탭을 6번째 탭으로 추가한 후, 설정 모달 너비(680px)가 부족하여 탭이 줄바꿈되거나 잘림.

### 해결

설정 모달 최대 너비를 `680px → 820px`로 확장.

```css
.stg-modal { max-width: 820px; }
```

### 교훈

- 탭 UI에 항목 추가 시 컨테이너 너비 재검토 필요
- 탭 수가 많아지면 스크롤 또는 드롭다운 전환 고려

## ISS-008: TC_03/TC_04 참조 음원 매핑 오류

| 항목 | 내용 |
|------|------|
| **심각도** | High (분석 정확도) |
| **영향 범위** | `types.ts`, `SettingsModal.tsx`, `useTcRunner.ts` |
| **소요 시간** | 중간 |
| **상태** | ✅ 해결됨 |

### 증상

보이스피싱 TC(TC_03/TC_04)에서 정답지(reference audio)가 잘못된 화자에 매핑되어 MOS 점수가 비정상적으로 낮게 나옴.

### 근본 원인

기존에는 하나의 `refAudioPath` 필드로 정답지를 관리했으나, 화자 1이 재생한 원본과 화자 2가 재생한 원본이 다른 경우를 처리하지 못함.

### 해결

`AudioProfile`에 **화자별 정답지** 필드를 분리:

```typescript
interface AudioProfile {
  refAudioPathS1?: string;  // S1이 재생 → iOS 수신 녹음과 비교
  refAudioPathS2?: string;  // S2가 재생 → Android 수신 녹음과 비교
}
```

레거시 `refAudioPath` 필드 폴백도 유지하여 기존 프로파일 호환성 보장.

### 교훈

- 양방향 통화 테스트에서는 화자별 음원/정답지가 항상 분리되어야 함
- 데이터 모델 변경 시 레거시 호환성(migration path) 고려
